# 코치코치 (CoachCoach)

자기소개서를 넣으면 맞춤 면접 질문을 만들고, 웹캠으로 녹화한 답변을 분석해 리포트를 주는 AI 모의면접 웹 서비스입니다.

대전대 AI SW중심대학 캡스톤디자인 경진대회에서 우수상을 받았습니다. 3인 팀(팀장 송경원)이 만들었고 2026년 6월에 배포한 뒤로 지금까지 직접 운영하고 있습니다.

## 기능

- 지원 직무와 자기소개서를 읽고 면접 질문 6개 생성 (외국어, 반말, 중복 질문은 걸러내고 모자라면 질문은행으로 채움)
- AI 면접관이 질문을 읽어 주면 브라우저에서 바로 답변 녹화
- 자세와 표정(MediaPipe), 음성 인식(Whisper), 답변 내용 평가(Ollama)를 합친 점수와 고칠 점
- 면접 기록과 점수 추이
- 공공데이터포털 공공기관 채용정보 API로 직무와 지역에 맞는 공고 표시

## 구조

웹과 DB는 항상 켜져 있어야 하니 클라우드에 두고, 가끔 돌지만 GPU가 필요한 AI 분석은 제 GPU PC(RTX 4070)에서 워커로 돌립니다.

```
[프론트엔드: React/Vite, Vercel]
        │ HTTPS (Cloudflare Tunnel)
        ▼
[백엔드: FastAPI + SQLite, AWS Lightsail]  로그인, 기록, 작업 큐
        ▲
        │ 워커가 주기적으로 일감을 가져감 (서버에서 PC로 호출하지 않음)
        │
[분석 워커: 개인 GPU PC]  MediaPipe, Whisper, Ollama
```

처음에는 EC2에 올렸다가 무료 크레딧이 끝날 무렵 월 고정 요금인 Lightsail로 옮겼습니다. DB와 설정은 백업해서 그대로 복원했고 월 예산 알림도 걸어 두었습니다.

서버가 PC를 직접 부르려면 PC의 인바운드 포트를 열어야 해서, 반대로 워커가 서버의 작업 큐를 주기적으로 확인하고 일을 가져가게 했습니다. 워커는 전용 키(`X-Worker-Key`)로만 인증하고, 비밀키는 저장소가 아니라 서버의 systemd 환경변수에 있습니다.

워커가 일을 가져간 채 멈추면 분석은 10분, 질문 생성은 5분 뒤 대기열로 돌아가고, 세 번 실패하면 실패로 처리합니다. AWS SQS의 가시성 타임아웃과 DLQ랑 같은 원리입니다. 워커는 하트비트를 보내는데 5분 넘게 신호가 없으면 서버가 맞춤 질문 대신 기본 질문은행을 씁니다. 워커 프로세스가 죽으면 15초 뒤 다시 켜집니다.

그 밖에 SQLite는 WAL 모드와 busy_timeout을 켜서 워커와 웹 요청이 동시에 써도 잠금 오류가 덜 나게 했고, 자세 분석 모델은 라이선스 때문에 YOLOv8(AGPL)에서 MediaPipe Pose(Apache 2.0)로 바꿨습니다.

## 메모리 측정

처음 분석 코드는 프레임 24장만 쓰면서 영상 전체를 메모리에 올리고 있었습니다. 프레임을 한 장씩 읽고 필요한 것만 남기도록 고친 뒤, 같은 테스트 영상으로 두 방식의 최대 메모리를 재 봤습니다. (2026-10-16, 프레임 읽기 단계만)

| 영상 | 예전 방식 (전체 적재) | 고친 방식 (스트리밍) |
|---|---|---|
| 640x480, 30초 | 1.6GB | 약 60MB |
| 640x480, 90초 | 4.8GB | 약 60MB |
| 1280x720, 30초 | 4.8GB | 약 150MB |
| 1280x720, 90초 | 14.4GB | 약 150MB |

예전 방식은 영상 길이에 비례해서 늘었고 고친 방식은 길이와 상관없이 거의 같았습니다. 3분짜리는 예전 방식으로 돌리면 PC 메모리를 넘을 것 같아서 재지 않았습니다.

## 개발 방식

구현은 AI 코딩 도구로 했고, 무엇을 만들지와 어디까지가 완성인지는 제가 정했습니다. 프로젝트 폴더에 작업 규칙과 완성 기준 문서를 두고 작업했고, 서버 코드는 다른 회사의 AI에게 교차 검토를 맡겼습니다. 위의 재시도 3회 제한도 그 검토에서 나온 것입니다.

출시 전에는 전공과 지원 직무가 다른 가상 사용자 200명(AI 페르소나)으로 테스트했습니다. 지금도 서버에 올리기 전에는 로컬에서 녹화부터 분석 결과 저장까지 한 번 끝까지 돌려 봅니다.

## 기술 스택

| 분야 | 사용 기술 |
|---|---|
| 프론트엔드 | React, Vite, Vercel |
| 백엔드 | FastAPI, SQLAlchemy, SQLite, JWT, bcrypt |
| AI 분석 | MediaPipe, Whisper base, Ollama (qwen2.5:7b), edge-tts |
| 인프라 | AWS Lightsail, Cloudflare Tunnel, systemd, AWS Budgets |

## 저장소

- frontend: 프론트엔드 (이 저장소)
- [backend-deploy](https://github.com/swsong02-prog/backend-deploy): 배포용 백엔드 (작업 큐와 워커 API 포함)

분석 워커 코드는 공개하지 않았습니다.

## 로컬 실행

```bash
npm install
npm run dev
```

백엔드 주소는 `VITE_API_URL` 환경변수로 넣습니다. (예: `VITE_API_URL=http://127.0.0.1:8000`)

## 아직 못 한 것

- 백엔드 서버가 한 대라 그 서버가 멈추면 서비스 전체가 멈춥니다.
- Cloudflare 임시 터널을 쓰고 있어서 서버를 재시작하면 주소가 바뀝니다.
- 분석 워커도 PC 한 대라 여러 건이 한꺼번에 들어오면 순서대로 기다립니다.
